# FN1001 — `DateTime.UtcNow` / `DateTime.Now` used directly inside a `[FilterOperator]` lambda

**Severity:** Warning

## What triggers it

The body of an `Expression<Func<...>>` operator references the system clock directly:

```csharp
[FilterOperator("withinDays")]
public static Expression<Func<DateTime, int, bool>> WithinDays =>
    (column, days) => column >= DateTime.UtcNow.AddDays(-days); // FN1001
```

## Why it matters

Each call materialises a fresh expression tree with a fresh `UtcNow` call inside. EF Core can usually translate it, but every invocation reads the database server's clock semantics rather than your application's "now". The result is order-of-operations dependent and hard to reason about.

## Fix

Use the method-shape override that pre-computes the cutoff in app-clock space, then inlines the literal into the predicate:

```csharp
[FilterOperator("withinDays")]
public static Expression<Func<DateTime, int, bool>> WithinDays(int days)
{
    var cutoff = DateTime.UtcNow.AddDays(-days);
    return column => column >= cutoff;
}
```
