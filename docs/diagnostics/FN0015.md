# FN0015 — Multiple filter profiles match property type

**Severity:** Error

## What triggers it

A property's CLR type has two or more `[FilterProfile<T>]`-annotated classes binding it, and the property's `[Map]` does not pin one with `Profile = typeof(...)`.

The most common shape: the user writes a custom `[FilterProfile<int>] CustomIntFilter` in their assembly while `Filtering.Net` already ships `[FilterProfile<int>] Int32Filter`. Both candidates are valid for an `int` property, and the generator can't pick.

The same conflict can fire for enums: every enum referenced by a `[GenerateFilter<TEntity>]` property gets an auto-emitted `Filtering.Net.Generated.<EnumName>Filter`, so a user-written `[FilterProfile<MyEnum>]` collides with the auto-emitted one.

## Why it matters

Picking either candidate silently could surprise the user. Forcing an explicit choice keeps the binding visible at the call site.

## Fix

Pin the profile on the `[Map]`:

```csharp
[Map(nameof(User.Id), Profile = typeof(CustomIntFilter))]
private static partial void MapId();
```

Or remove the redundant profile if the duplication was unintentional.

## See also

- **FN0005 IncompatibleProfile** — fires when the explicitly-mapped profile's `T` doesn't match the property's CLR type.
- **FN0009 NoInferableProfile** — the opposite case: zero candidates instead of multiple.
