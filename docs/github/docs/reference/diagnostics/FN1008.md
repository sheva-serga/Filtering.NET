# FN1008 — Filter value type is not registered in any visible JsonSerializerContext

**Category:** Filtering.Net
**Severity:** Warning (default)
**Opt-in:** Requires `[assembly: FilterValueDiagnostics(WarnUnregistered = true)]`

## What triggers this

Filtering.Net emits `JsonSerializer.Deserialize` calls for **Path B** filter value extraction:

- `[FilterOperator]` custom-operator value parameters.
- `[PropertyMap]` override operator value parameters.

Under NativeAOT or aggressive trimming, these calls require source-generated metadata via a `JsonSerializerContext`. When you opt in via the assembly attribute, the analyzer walks every Path B value type in your filter classes and checks whether any `JsonSerializerContext` visible in the compilation declares `[JsonSerializable(typeof(T))]` for that type. If none does, FN1008 fires at the declaration site.

## How to fix

### Option 1 — register the type

Add the type to a `JsonSerializerContext` in your assembly:

```csharp
[JsonSerializable(typeof(MyCustomValueType))]
internal partial class MyAppJsonContext : JsonSerializerContext;
```

Then wire the context into Filtering.Net at startup:

```csharp
services.AddFiltering(MyAppJsonContext.Default);
```

If you want both source-gen and reflection fallback (e.g., for non-AOT debug builds):

```csharp
services.AddFiltering(JsonTypeInfoResolver.Combine(
    MyAppJsonContext.Default,
    new DefaultJsonTypeInfoResolver()));
```

### Option 2 — drop the opt-in

If your app doesn't target NativeAOT and reflection-based deserialization is acceptable, remove the assembly attribute (or set `WarnUnregistered = false`):

```csharp
// Remove this line, or change to WarnUnregistered = false
[assembly: FilterValueDiagnostics(WarnUnregistered = true)]
```

Reflection-based extraction continues to work for any value type without registration.
