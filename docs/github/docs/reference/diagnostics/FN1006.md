# FN1006 — Path crosses a nullable navigation property

**Severity:** Warning

## What triggers it

A `[Map("Department.Name")]`-style dotted path traverses a navigation that's typed as nullable on the entity (e.g., `User.Department` is `Department?`).

## Why it matters

EF Core handles null-propagation transparently in most cases, but client-projection paths or `EF.Functions.*` calls inside an interceptor can diverge from the SQL provider's behaviour. Explicit null handling makes the intent visible at the source.

## Fix

Either:
1. Mark the navigation as required on the EF model so the warning becomes incorrect (make `Department` non-nullable in the entity).
2. Move to a `[PropertyMap]` override and write the accessor with explicit null guards: `entity => entity.Department != null ? entity.Department.Name : null`.
3. If you've audited the SQL output and accept the default null-propagation, suppress with `#pragma warning disable FN1006`.
