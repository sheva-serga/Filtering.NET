# FN0016 — Standalone filter profile is missing a required extractor method

**Severity:** Error

## What triggers it

A `[FilterProfile<T>]` class with no `BasedOn` argument declares one or more `[FilterOperator]` members but is missing the corresponding extractor method(s):

- Any scalar-shape operator (`eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `contains`, `startsWith`, `endsWith`, or any custom non-`in`/non-`isNull` operator) requires a `public static TryGetValue(JsonElement, out T, out string)` method.
- The `in` operator requires a `public static TryGetArray(JsonElement, out T[], out string)` method.

## Why it matters

The source generator emits validation and predicate-building code that calls `{Profile}.TryGetValue(...)` / `{Profile}.TryGetArray(...)` directly. Standalone profiles (those that don't inherit from a built-in via `BasedOn`) are responsible for providing those extractors themselves; if they don't, the emitted code references a method that doesn't exist and the consumer compilation fails with a confusing `CS0117` error pointing at generator output.

## Fix

Either:

1. Declare the missing extractor method(s) on the profile, e.g.:

   ```csharp
   public static bool TryGetValue(JsonElement element, out MyType value, out string error) { ... }
   public static bool TryGetArray(JsonElement element, out MyType[] values, out string error) { ... }
   ```

2. Or set `BasedOn = typeof(SomeBuiltInProfile)` so the profile inherits the extractors from a profile that does:

   ```csharp
   [FilterProfile<string>(BasedOn = typeof(StringFilter))]
   public static class MyStringExtensions
   {
       [FilterOperator("fuzzy")]
       public static Expression<Func<string, string, bool>> Fuzzy => (col, val) => EF.Functions.Like(col, $"%{val}%");
   }
   ```

A profile that *only* declares `isNull` operators (no scalar, no `in`) doesn't need either extractor and doesn't trip this rule.

## Note on signatures

The analyzer checks for a `public static` method by name only. If the method exists with a wrong signature, the consumer-side compilation surfaces the mismatch.
