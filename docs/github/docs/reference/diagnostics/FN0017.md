# FN0017 — Duplicate operator declaration on profile

**Severity:** Error

## What triggers it

A `[FilterProfile<T>]` class declares the same operator name on more than one `[FilterOperator]`-marked member:

```csharp
[FilterProfile<Guid>]
public static class GuidFilter
{
    [FilterOperator("eq")]
    public static Expression<Func<Guid, Guid, bool>> Eq => (column, value) => column == value;

    [FilterOperator("eq")] // FN0017 fires on this duplicate
    public static Expression<Func<Guid, Guid, bool>> EqAlt => (column, value) => column == value;
}
```

The check is case-sensitive and per-profile. Operators with the same name declared on a *base* profile (via `BasedOn = typeof(...)`) and an inheriting profile are not duplicates — the inheriting profile is intentionally overriding.

## Why it matters

Operator dispatch is keyed by name. Two declarations for `"eq"` mean the generator silently picks one (whichever the Roslyn member iteration order surfaces first); the other is dead code that misleads readers and shifts behaviour if the source order changes. Worse, the picked declaration may not be the one the author intended.

## Fix

Pick one declaration and delete the other, or rename one to a distinct operator (`"eqStrict"`, `"eqIgnoreCase"`, etc.):

```csharp
[FilterProfile<Guid>]
public static class GuidFilter
{
    [FilterOperator("eq")]
    public static Expression<Func<Guid, Guid, bool>> Eq => (column, value) => column == value;
}
```

The first occurrence is silent; only the second and later duplicates fire FN0017, so the location reported is the duplicate to remove or rename.
