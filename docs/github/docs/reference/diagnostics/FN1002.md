# FN1002 — Property likely should be sortable

**Severity:** Warning

## What triggers it

A `[Map]` targets a property whose CLR type is "naturally sortable" (string, number, DateTime, etc.) but the mapping omits `Sortable = true`.

## Why it matters

Most filterable surfaces also need to be sortable. Forgetting `Sortable = true` means clients can filter on `Age` but can't ask the API to order by it — usually a bug, occasionally a deliberate omission.

## Fix

If the property should be sortable, add `Sortable = true`. If you specifically don't want clients to sort by it (e.g., to avoid an unindexed sort), suppress the warning at the call site with `#pragma warning disable FN1002`.
