# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - 2026-09-20

The filter engine moved from generated code into the runtime. The generator now emits a small typed schema per filter class, and `FilterDefinition<TEntity>` validates requests, composes predicates, and applies sorting for every filter. A filter with two string properties went from 347 emitted lines to about 25. `[Map]` and `[MapNested]` moved from marker methods onto the filter class, so a filter no longer needs any empty partial methods.

### Changed
- **Breaking:** `[Map]`, `[MapNested]`, and `[MapNested<TFilter>]` are class-level attributes (`AllowMultiple`). Move each one from its `private static partial void MapX();` method onto the `[GenerateFilter<T>]` class and delete the method. Leaving one on a method is now a C# compiler error (CS0592). `[InterceptValue]` and `[PropertyMap]` stay on methods, because those methods have bodies.
- **Breaking: analyzer ids renumbered once for this release.** Two rules were removed (`DuplicateSortable`, and `MissingPartial`, which cannot occur without marker methods), and the ids stay contiguous. Mapping from 0.1.2: `FN0003 MapAndPropertyMapBoth` → `FN0002`, `FN0004 PropertyNotFound` → `FN0003`, `FN0005 IncompatibleProfile` → `FN0004`, `FN0006 UnknownOperator` → `FN0005`, `FN0008 NoInferableProfile` → `FN0006`, `FN0009 DuplicateInterceptor` → `FN0007`, `FN0010 NonStaticOperator` → `FN0008`, `FN0011 AliasCollision` → `FN0009`, `FN0012 InvalidBaseProfile` → `FN0010`, `FN0013 InterceptorWithoutMap` → `FN0011`, `FN0014 AmbiguousProfile` → `FN0012`, `FN0015 ProfileMissingExtractor` → `FN0013`, `FN0016 DuplicateOperatorOnProfile` → `FN0014`. New in this release: `FN0015 NestedCycle`, `FN0016 NestedCrossAssembly`, `FN0017 NestedAmbiguous`, `FN0018 NestedTargetNotFound`, `FN0019 NestedNavigationInvalid`, `FN0020 NestedCollectionUnsupported`, `FN0021 FilterClassHasBaseType`, `FN0022 NestedMaxDepthInvalid`. Warnings (`FN1001`–`FN1008`) are unchanged. Final surface: 22 errors + 8 warnings = 30 rules.
- **Breaking: `FN0013 ProfileMissingExtractor` removed, and the ids above it renumbered a second time for this release.** A standalone `[FilterProfile<T>]` no longer has to declare `TryGetValue` / `TryGetArray`: value operators on user profiles deserialize through System.Text.Json with the filter definition's resolver, so nothing generated ever called those methods. With the rule gone the ids stay contiguous. Mapping from the list above: `FN0014 DuplicateOperatorOnProfile` → `FN0013`, `FN0015 NestedCycle` → `FN0014`, `FN0016 NestedCrossAssembly` → `FN0015` (also renamed `NestedFilterClassUnusable`, see below), `FN0017 NestedAmbiguous` → `FN0016`, `FN0018 NestedTargetNotFound` → `FN0017`, `FN0019 NestedNavigationInvalid` → `FN0018`, `FN0020 NestedCollectionUnsupported` → `FN0019`, `FN0021 FilterClassHasBaseType` → `FN0020`, `FN0022 NestedMaxDepthInvalid` → `FN0021`, `FN0023 ProfileTypeNotAProfile` → `FN0022`, `FN0024 PropertyMapSignatureInvalid` → `FN0023`, `FN0025 NullableValueTypeInPath` → `FN0024`, `FN0026 NestedPrefixBlank` → `FN0025`, `FN0027 NestedPathFilterUnknown` → `FN0026`. Also new in this release: `FN0027 FilterClassPlacementInvalid`, `FN0028 OperatorMemberShapeInvalid`, `FN0029 InterceptorSignatureInvalid`. Warnings (`FN1001`–`FN1008`) are unchanged. Final surface: 29 errors + 8 warnings = 37 rules.
- **Breaking:** `[PageSettings]` takes plain `int` properties. `DefaultPageSize` and `MaxPageSize` were `int?`, which C# rejects as an attribute-argument type (CS0655), so the attribute could not be applied with either value. Omit a named argument to inherit it from `[assembly: FilterDefaults]`.
- `ApplyPagedAsync` with neither `page` nor `pageSize` still does not page, and now reports the whole filtered set as one page (`PageSize = TotalCount`, `TotalPages = 1`). Paging without a sort stays the caller's responsibility and is documented on the method.
- Sample: the `fuzzy` operator lowers both sides, and the read-only endpoints use `AsNoTracking()`.
- **Breaking:** `FN0015` (was `FN0016 NestedCrossAssembly`) is renamed `NestedFilterClassUnusable` and reworded. It fires for any `[MapNested<T>]` whose `T` is not a `[GenerateFilter<TNavigation>]` partial in this compilation — a non-filter type and a filter for a different entity both reach it — so the old "declared in another assembly" wording was wrong for most of the cases it covered.
- **Breaking:** generated filter classes derive from `FilterDefinition<TEntity>`. A `[GenerateFilter]` partial can no longer declare its own base class; new error `FN0020 FilterClassHasBaseType` reports it.
- A `[FilterProfile<T>(BasedOn = ...)]` profile that re-declares an inherited operator is a legal override: the derived operator replaces the inherited one and keeps its position in the operator order. The emitted profile bridge now calls `FilterProfile<T>.ExtendWithOverrides` instead of `Extend`, which threw `FilterConfigurationException` from the generated static initialiser for exactly that source.
- `FN0013 DuplicateOperatorOnProfile` compares operator names case-insensitively, matching the runtime profile's operator dictionary.
- Auto-emitted enum profiles are named after the enum's fully-qualified name whenever two enums in the compilation share a simple name. Previously both produced `Filtering.Net.Generated.<Name>Filter` and the same `AddSource` hint name, which failed the entire generator run (CS8785) and dropped every generated filter class.
- Every analyzer diagnostic now carries the registered descriptor's `helpLinkUri` and `description`. Rules reported from the extractors previously reached the compiler and the IDE with an empty help link.
- `FN1008 FilterValueTypeUnregistered` sees `[JsonSerializable(typeof(T[]))]` registrations and `JsonSerializerContext` types nested more than one level deep, and is reported once per distinct value type and declaration site instead of once per property and per `[MapNested]` splice path.
- **Breaking (source):** `IFilterDefinition<TEntity>` gained `int ResolvePageSize(int? requestedPageSize)`. Filters that derive from `FilterDefinition<TEntity>` — every generated one — inherit it; a hand-written implementation of the interface has to add it.
- **Breaking:** `SortItem.Dir` is now `SortDir?`. An omitted direction uses the property's `DefaultSortDirection`, which was previously ignored.
- **Breaking:** validation now rejects several request shapes it used to pass through to the query provider: a sort item with a missing or empty `field` (`NotSortable`), a `dir` outside the `SortDir` enum (`InvalidSortDirection`, declared since 0.1.0 but never produced before), a `not` group whose child count is not exactly one and a group combinator outside `LogicalOp` (both `InvalidNodeShape`), a `page` whose skip offset overflows `int` (`PageInvalid`), and a JSON `null` supplied to an operator that takes a typed value (`InvalidValueType`).
- `Filtering.Net` multi-targets `netstandard2.0;net8.0`. The `netstandard2.0` asset keeps the PolySharp polyfills and the `System.Text.Json` package reference; the `net8.0` asset needs neither and is the only one that ships `DateOnlyFilter` and `TimeOnlyFilter`, whose `DateOnly` / `TimeOnly` types do not exist under `netstandard2.0`.
- `MapNullable` predicates that read the column outside a comparison — `column.Year`, `column % 2` — are wrapped in a `HasValue` guard, so null rows are excluded (`IS NOT NULL` for a provider) instead of throwing when the query runs in memory.
- Every numeric profile parses JSON strings through one shared contract, `NumericExtractor.InvariantNumberStyles` (`Number | AllowExponent`, invariant culture). The same literal is now accepted on every numeric column type, and a value accepted as a JSON Number is accepted as the equivalent JSON String.
- Array validation messages are uniform across the string, numeric, Guid and enum profiles: a non-array value reports `Expected JSON Array, got {kind}.`, and a bad element reports `Array element [i]: {element error}`.
- A `FilterLeaf` whose JSON object has no `value` member now deserializes, carrying a `JsonValueKind.Undefined` element. That is how a unary operator such as `isNull` is sent; previously the member had to be present.
- `FilterSchema<TEntity>.LiftInto` validates its arguments: a blank prefix throws, an `only` / `except` entry with no dot that the nested schema does not expose throws, and an explicitly empty `only` allows no direct property (`null` remains "no restriction"). Dotted entries stay unchecked, because a bounded nesting legitimately drops the paths they name.
- `FilterPropertyBuilder.Alias` throws on a blank alias, and `FilterRuleBuilder.For` throws when called twice instead of silently re-pointing the operators declared before it.
- `FN1002 NotSortableLikelyOmission` is anchored at the `[Map]` attribute rather than the class, so it is navigable and `#pragma`-suppressible per property.
- `FN1003 ProfileUnused` and `FN1004 OperatorUnused` count the whole `BasedOn` chain as referenced. A base profile reached only through a derived profile's `BasedOn` no longer warns as unused, and neither do the operators a `[Map]` inherits from it.
- The generator's `[PropertyMap]` extractor scans the whole method body rather than the returned fluent chain, so a statement-bodied rule keeps its operators — and with them its typed-value detection and the resolver-accepting constructor.
- The incremental pipeline was restructured around a single `GeneratorIndex` node built from `CompilationProvider`: it carries the profile index, the auto-emitted enum profile descriptors, the assembly-level `[FilterDefaults]`, the DI-reference flag and the FN1008 `[JsonSerializable]` registrations. Extraction is now two-phase — a syntax transform reading only the class's own tree, then a resolver that combines it with the index — so a change in one file can no longer leave another file's cached model stale.
- **Breaking:** `MaxNestingDepth` and `MaxLeafConditions` from `[assembly: FilterDefaults]` are now enforced during validation (`NestingTooDeep`, `TooManyConditions`). They were declared but never checked. Defaults are 10 and 50.
- **Breaking:** `LeafValidation` and `PageValidation` are internal. They were public only because generated code called them.
- **Breaking:** `FilterRule<TEntity, TValue>.Operators` is now `IReadOnlyList<FilterOperator<TValue>>`.
- Predicates are composed at request time from compiler-checked accessor and operator lambdas, by parameter substitution. There is still no reflection over consumer types and no `Compile()`; trim and Native AOT behaviour is unchanged.
- `[MapNested]` reuses the nested filter's schema at runtime instead of copying its mappings into the host. `[InterceptValue]` methods and `[PropertyMap]` rules on the nested filter now carry through, which removes the corresponding 0.1.x limitation.
- `[InterceptValue]` and `[PropertyMap]` methods may be `private`.
- `[PropertyMap]` methods run once when the filter is constructed. `FilterRuleBuilder` is a real builder rather than a compile-time marker.
- `[InterceptValue]` with an array parameter applies to array operators such as `in`, and `Raw = true` replaces scalar parsing. Both were documented but not wired before.
- Project-wide diagnostic location enrichment: every analyzer rule that has multi-site context now reports `additionalLocations` so the IDE Error List, Rider Inspections panel, and `dotnet build` output surface every relevant site (e.g. both `[Map]` declarations on a duplicate-mapping error). See the diagnostics catalogue for the per-rule audit.

### Added
- `MaxDepth` on `[MapNested]` and `[MapNested<TFilter>]`. A self-referencing or circular filter graph (`Employee.Manager`, or `User.Department` with `Department.Head`) is now allowed when at least one nesting in the cycle declares `MaxDepth`; that nesting is followed at most that many times along one path. Cycles with no `MaxDepth` still raise `FN0014 NestedCycle`. A value of 1–64 bounds the nesting and the default `0` leaves it unbounded; new error `FN0021 NestedMaxDepthInvalid` rejects a negative `MaxDepth` (meaningless) and one above the supported ceiling of 64 (it would expand into an unusable number of filter paths). Runtime counterpart: `FilterSchemaBuilder.AddNested` and `FilterNestingContext`, which also turn an unbounded cycle in a hand-built schema into a `FilterConfigurationException`. (Ids here are the final ones for this release; see the renumbering entries above.)
- Public runtime API for building definitions without the generator: `FilterDefinition<TEntity>`, `FilterSchema<TEntity>`, `FilterSchemaBuilder<TEntity>`, `FilterSettings`, `FilterProperty<TEntity>`, `FilterProperty.Map` / `MapNullable` / `MapRule`, `FilterPropertyBuilder<TEntity, TColumn>`, `FilterProfile<TColumn>`, `FilterOperator<TColumn>` and its factories, `TryParseValue<TValue>`.
- `Profile` accessor on every built-in profile, and on auto-emitted enum profiles.
- `IFilterDefinition<TEntity>.ResolvePageSize(int?)` — the page size `ApplySorting` will actually apply, after the schema's `DefaultPageSize` and `MaxPageSize`. `ApplyPagedAsync` reports it in `PageResult<T>.PageSize` instead of echoing the requested value, so a request with `page` but no `pageSize` no longer reports the returned row count as the page size.
- `FilterProfile<TColumn>.ExtendWithOverrides(name, declaredOperators)` — inherit every operator of a profile, with a declared operator replacing an inherited one of the same name (case-insensitive) in place. `Extend` keeps its existing behaviour of throwing on a re-declared inherited name; both still throw when one call declares the same name twice.
- `FilterValidationCode.InvalidNodeShape` for a node the engine cannot interpret: a `not` group without exactly one child, a group combinator outside `LogicalOp`, or a `FilterNode` subtype that is neither `FilterGroup` nor `FilterLeaf`.
- `NumericExtractor.InvariantNumberStyles`, the `NumberStyles` value shared by all seven numeric profiles' string parsing.
- `FilterDefinition<TEntity>.Schema` for introspection of fields, aliases, operators, and sortable flags.
- `FilterRuleBuilder.Operator(name, predicate)` overload for operators that take no value.
- `FilteringProfiles.g.cs`: one emitted runtime `FilterProfile<T>` instance per custom profile referenced by the assembly's filters.
- Eight error diagnostics for shapes that previously compiled and then misbehaved at runtime (final ids): `FN0022 ProfileTypeNotAProfile` (`[Map(Profile = typeof(X))]` naming a type with no `[FilterProfile<TColumn>]`), `FN0023 PropertyMapSignatureInvalid` (a `[PropertyMap]` method the generated `CreateSchema` cannot call, which used to drop the property silently), `FN0024 NullableValueTypeInPath` (a dotted `[Map]` reading a member through a `Nullable<T>` segment), `FN0025 NestedPrefixBlank` (a present-but-blank `[MapNested(Prefix = ...)]`), `FN0026 NestedPathFilterUnknown` (a dotless `[MapNested]` `Only` / `Except` entry the nested filter does not map), `FN0027 FilterClassPlacementInvalid` (a `[GenerateFilter]` class that is nested in another type or generic, so the generated top-level partial would never join it), `FN0028 OperatorMemberShapeInvalid` (a `[FilterOperator]` member whose type is not an operator template), and `FN0029 InterceptorSignatureInvalid` (an `[InterceptValue]` method that would not compile or would never run).
- `[MapNested]` and `[MapNested<TFilter>]` attributes for compile-time filter inlining via navigation properties. The generator splices another `[GenerateFilter<TNav>]` partial's `[Map]` mappings (with `Sortable`, `Alias`, `Only`/`Except`, custom `[FilterOperator]` bodies) into the host filter under a dotted prefix at compile time. Reference navigations only; collection navigations are deferred. New error diagnostics `FN0014` to `FN0019`, plus `FN0025 NestedPrefixBlank` and `FN0026 NestedPathFilterUnknown` (final ids; see the id mapping above). `FN0001 DuplicateMapping` broadened to cover any duplicate effective dotted path across `[Map]`, `[PropertyMap]`, and `[MapNested]`, with multi-source-list message and `additionalLocations` reporting.

### Removed
- `[FilterValidator]` attribute. The generator never read it.
- `MissingPartial` analyzer rule (`FN0007` in 0.1.2). `[Map]` no longer sits on a method, so it cannot occur.
- `DuplicateSortable` analyzer rule (`FN0002` in 0.1.2). It was a value-aware refinement of `FN0001` that didn't change the user's required action; both cases now fold into `FN0001 DuplicateMapping`. Suppressions like `dotnet_diagnostic.FN0002.severity = none` become silent no-ops; remove them at your convenience.

## [0.1.2] - 2026-05-07

### Removed
- `[ConvertWith<TConverter>]` attribute and the `FN0007 InvalidValueConverter` diagnostic. EF Core value converters are configured on the model side via `HasConversion<>` in `OnModelCreating`; once registered, EF translates the predicate against the property's CLR type without any Filtering.Net hint. The attribute documented behavior it did not contribute to and carried a latent bug on the nullable-enum path. Consumers using `[ConvertWith<>]` should remove it — no replacement is needed.

### Changed
- **Analyzer diagnostic IDs renumbered to stay contiguous** after the FN0007 removal. Errors `FN0008`–`FN0017` shift down by one to `FN0007`–`FN0016`. Mapping: `FN0008 MissingPartial` → `FN0007`, `FN0009 NoInferableProfile` → `FN0008`, `FN0010 DuplicateInterceptor` → `FN0009`, `FN0011 NonStaticOperator` → `FN0010`, `FN0012 AliasCollision` → `FN0011`, `FN0013 InvalidBaseProfile` → `FN0012`, `FN0014 InterceptorWithoutMap` → `FN0013`, `FN0015 AmbiguousProfile` → `FN0014`, `FN0016 ProfileMissingExtractor` → `FN0015`, `FN0017 DuplicateOperatorOnProfile` → `FN0016`. Warnings (`FN1001`–`FN1008`) are unchanged. Final analyzer surface: 16 errors + 8 warnings = 24 rules.
- Every diagnostic's `helpLinkUri` now points at a single catalogue page (`https://sheva-serga.github.io/Filtering.NET/diagnostics/`) instead of per-rule explainer pages. Future renumbering is no longer a help-link breaking change.
- Documentation restructured: the `Reference` section (40+ per-attribute / per-type / per-rule pages) collapsed into a single `Diagnostics catalogue` table; mkdocs path moved from `docs/reference/diagnostics/` to `docs/diagnostics/`.

## [0.1.0] - 2026-05-05

### Added
- `Filtering.Net` runtime: `[GenerateFilter<T>]` attribute set, `FilterRequest` / `FilterNode` types, `IFilterDefinition<T>`, built-in profiles, `IQueryable.Apply`.
- `Filtering.Net.Generator`: Roslyn incremental source generator + 24-rule analyzer (FN0001–FN0016 errors, FN1001–FN1008 warnings).
- `Filtering.Net.EntityFrameworkCore`: `ApplyPagedAsync` + `PageResult<T>`; `net10.0` / EF Core 10 target alongside `net8.0` and `net9.0`.
- MkDocs documentation site under `docs/`.
- GitHub Actions workflow `nuget.yml` for tag-driven NuGet.org publishing of all three packages.

### Security
- Bumped EF Core floor versions to `8.0.13` / `9.0.5` / `10.0.0` to patch [GHSA-qj66-m88j-hmgj](https://github.com/advisories/GHSA-qj66-m88j-hmgj) (NU1903) in transitive dependencies.
